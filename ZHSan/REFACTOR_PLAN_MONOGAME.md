# ZHSan 全面重构方案（MonoGame 现代化）

> 目标：在保持玩法与数据兼容的前提下，对项目进行“从上到下、从里到外”的系统重构，优先采用成熟开源方案，减少手搓代码，提升可维护性、扩展性、性能与跨平台稳定性。

---

## 0. 当前代码基线与核心问题（结合现有实现）

### 0.1 主循环与全局状态耦合严重
- `MainGame` 内聚合了启动、显示切换、平台控制、截图、告警等多种职责，存在“超大入口类”。
- `Session` 全局单例在各层大量穿透，业务、UI、渲染、输入边界不清晰。
- 结论：需要拆分为 `Bootstrap / Runtime / Domain / Presentation` 分层。

### 0.2 UI 系统碎片化，插件式 UI 实际是手工拼装
- `GamePlugin.InitializePlugins` 中硬编码逐个 new/SetXXX/Add，缺少声明式布局与主题系统。
- 大量 UI 插件（对话框、列表、工具栏、侧栏）重复“绘制+输入+状态”逻辑。
- 结论：统一迁移到 Myra UI，并引入适配层逐步替换。

### 0.3 动画能力偏基础帧动画
- `AnimatedTexture` 主要支持序列帧切换，缺乏时间线、补间、曲线、组合动画、事件回调。
- 现状难以支持高表现力特效（粒子、屏幕后处理反馈、命中特效联动）。
- 结论：建立独立动画/特效子系统，支持 Sprite 动画 + Tween + 粒子 + Camera FX。

### 0.4 摄像机与视图移动能力较弱
- `ViewMove` 仅枚举方向，缺少“目标跟随、阻尼、边界约束、优先级、冲击效果”。
- 结论：重构为可配置 Camera Controller，加入震屏、红屏、镜头粒子叠加等系统。

### 0.5 游戏流程层代码过重
- `ScreenManager` 含大量业务流程分支与 UI 交互耦合，维护成本高。
- 结论：改为 Command + UseCase + EventBus 模式，拆分城池内政/军事/外交用例。

## 1. 重构总目标与原则

## 1.1 总目标
1. UI：全面迁移到 **Myra UI**，形成统一组件体系、布局体系、主题体系。
2. 动画：建立现代动画管线，支持 **粒子动画**、**补间动画**、组合时间线与事件触发。
3. 摄像机：构建新 Camera 系统，支持 **跟随**、**震屏**、**红屏**、**镜头粒子特效**。
4. 架构：降低 `Session` / Screen / Plugin 耦合，实现可测试、可扩展、可替换模块化。
5. 工程：引入质量门禁（格式化、静态分析、基础测试、性能指标）。

## 1.2 执行原则
- 玩法不变优先：重构阶段保证核心规则与数值行为一致。
- 渐进替换：采用“兼容层 + 双栈并行”，避免一次性推倒重写。
- 可观测性优先：每阶段必须可量化验证（FPS、内存、UI 响应、加载时长）。
- 开源优先：优先使用稳定社区方案，手写只做胶水层与业务层。

## 2. 分层重构蓝图（建议目标架构）

- `ZHSan.Core.Domain`：规则、实体、回合推进、AI、战斗/内政逻辑（纯逻辑，尽量无 XNA 依赖）。
- `ZHSan.Core.Application`：用例层（命令、查询、流程编排、事件）。
- `ZHSan.Core.Presentation`：UI（Myra）、输入映射、屏幕状态机、HUD。
- `ZHSan.Core.Rendering`：地图渲染、动画、粒子、相机、后处理。
- `ZHSan.Core.Infrastructure`：资源加载、存档、配置、日志、平台抽象。

补充：短期可不拆项目文件，先按命名空间分层；中期再物理拆分 csproj。

## 3. UI 系统重构（Myra UI）

## 3.1 目标范围
- 所有面板/对话框/菜单/列表/输入器迁移到 Myra。
- 统一字体、边距、配色、层级、动效节奏、热区行为。
- 支持键鼠/手柄输入导航与焦点管理。

## 3.2 重点改造对象（结合当前插件）
- 菜单与上下文：ContextMenu、OptionDialog、ConfirmationDialog。
- 详情面板：PersonDetail、TroopDetail、ArchitectureDetail、TreasureDetail。
- 列表体系：TabList、youcelan、BianduiLiebiao。
- 系统面板：ToolBar、GameRecord、Help、MapLayerSelector。

## 3.3 实施方案
1. 建 `IMyraViewAdapter`：封装 Show/Hide/Bind/Dispose，与旧插件接口兼容。
2. 建 `UiTheme` 与 `UiStyleTokens`：统一字号、颜色、间距、按钮状态。
3. 建 `UiNavigationService`：焦点环、快捷键、手柄方向键导航。
4. 建 `UiBinding` 层：将 Domain DTO 映射为 Myra ViewModel。
5. 逐插件替换：每次替换一个插件并保留旧版开关（Feature Flag）。

## 3.4 验收标准
- 所有旧 UI 插件可被同名 Myra 版本替换。
- 关键界面 1080p 下不溢出，4K 缩放不失真。
- UI 输入延迟（点击到反馈）< 100ms（本地基线机）。

## 4. 动画系统重构（帧动画 + Tween + 粒子）

## 4.1 动画系统能力目标
- `IAnimationPlayer`：统一更新与播放控制（Play/Pause/Stop/Seek）。
- `Tween`：支持位置/缩放/旋转/透明度/颜色插值，含 Easing 曲线。
- `Timeline`：支持并行/串行组合，节点事件回调（命中、结束、循环）。
- `Particle`：支持发射器、生命周期、速度场、颜色渐变、贴图帧。

## 4.2 替换现状策略
- 保留 `AnimatedTexture` 作为 `LegacySpriteAnimationAdapter`。
- 新增 `SpriteAnimationClip` + `TweenTrack` + `ParticleEmitter`。
- 通过 `EffectOrchestrator` 统一调度（战斗、事件、UI 引导等）。

## 4.3 粒子系统落地场景
- 战斗命中火花、烟尘、箭矢轨迹、技能释放。
- 城市事件提示（升级、灾害、资源变化）。
- UI 反馈粒子（按钮点击、达成成就）。

## 4.4 验收标准
- 同屏 500~2000 粒子稳定运行（目标平台分档）。
- 动画脚本可配置（JSON 或数据表），无需每次改代码。
- 动画与逻辑解耦（逻辑发事件，表现层订阅）。

## 5. 摄像机与镜头特效重构

## 5.1 新 Camera 架构
- `CameraState`：位置、缩放、旋转、边界、平滑参数。
- `CameraController`：目标跟随、插值移动、阻尼、预测跟随。
- `CameraEffectStack`：震屏、红屏、模糊、边缘暗角、镜头粒子叠加。

## 5.2 关键特效定义
1. 震屏（Shake）
   - 参数：强度、频率、衰减、轴向（X/Y/XY）、叠加策略。
2. 红屏（Damage Flash）
   - 参数：颜色、透明度曲线、持续时间、叠加上限。
3. 镜头粒子（Camera-space Particles）
   - 参数：屏幕空间发射区域、深度层级、混合模式。

## 5.3 跟随策略
- 软跟随（Lerp/SmoothDamp）用于常规移动。
- 硬锁定用于剧情演出。
- 多目标框选（按目标包围盒自动缩放）。

## 5.4 验收标准
- 镜头移动无明显抖动，目标切换延迟可控。
- 特效触发不影响输入判定与 UI 可操作性。
- 战斗高峰帧率下降可控（定义阈值并压测）。

## 6. 除你提出内容外，建议同步重构点（必须一起做，避免“表层翻新”）

1. **输入系统统一**：键鼠/触屏/手柄输入映射表化，去散落判断。  
2. **事件总线**：用 `DomainEvent` / `UiEvent` 解耦 ScreenManager 巨型流程。  
3. **资源管线**：纹理、字体、音效元数据化，支持异步加载与引用计数。  
4. **存档系统升级**：版本化存档结构，兼容旧存档迁移器。  
5. **日志与诊断**：统一日志级别、崩溃快照、性能计时点。  
6. **测试体系**：为核心规则、回合推进、关键 UI 交互建立自动化测试。  
7. **性能治理**：对象池、批渲染优化、热点分配跟踪、GC 抖动压制。  
8. **插件治理**：把当前硬编码插件注册改为配置化发现/装配。  
9. **本地化与字体**：文本资源统一管理，中文字形与 fallback 策略完善。  
10. **工程现代化**：升级目标框架与依赖、CI、格式化、静态分析规则。

## 7. 里程碑计划（先文档后开发）

### M0：架构与规范冻结（1~2 周）
- 产出：架构图、模块边界、编码规范、命名规范、性能预算、UI 设计令牌。
- 决策：Myra 接入方式、动画库选型、粒子方案、后处理方案。

### M1：UI 基座迁移（2~4 周）
- 完成 Myra Runtime、主题系统、基础控件适配。
- 先迁移主菜单/设置/确认弹窗等低风险界面。

### M2：动画与特效基座（2~4 周）
- 建成 Tween、Timeline、Particle 最小可用体系。
- 先替换一条战斗表现链路做基准。

### M3：摄像机系统替换（2~3 周）
- 上线跟随、震屏、红屏、镜头粒子。
- 与战斗事件/剧情事件打通。

### M4：流程与插件解耦（3~6 周）
- 拆 ScreenManager 重流程，替换为 UseCase + EventBus。
- 插件装配配置化，逐步移除硬编码初始化。

### M5：全面回归与发布（2~3 周）
- 功能回归、性能回归、存档兼容验证。
- 发布迁移说明与开发者文档。

## 9. 风险与缓解

- **风险 1：一次性替换导致功能雪崩**  
  缓解：Feature Flag + 双栈并行 + 小步发布。

- **风险 2：UI 迁移后交互细节退化**  
  缓解：建立“UI 行为回归清单”和录屏对比基线。

- **风险 3：特效提升导致性能回退**  
  缓解：分级质量档（Low/Medium/High）+ 运行时动态降级。

- **风险 4：存档不兼容**  
  缓解：版本迁移器 + 自动备份 + 回滚入口。

## 10. 建议采用的开源方向（用于调研与选型）

- UI：**Myra**（核心 UI 框架，统一替换手搓 UI）。
- 动画：Tween 库（或自建轻量 Tween Core）+ 数据驱动时间线。
- 粒子：MonoGame 生态粒子方案（优先可维护、可序列化配置者）。
- 架构：依赖注入（轻量容器）+ 事件总线 + 配置化装配。
- 诊断：性能分析工具与结构化日志方案。
